# 單字大冒險（english-word-quest）

小三英文家教用的單字練習 PWA。單檔 HTML，沿用 `chinese-word-quest`（生字大冒險）的遊戲外殼，
核心關卡整個換成英文，目的是讓孩子自己在家練，不是老師在旁邊改。

## 首頁＝家長提案的「每天 20 分鐘」

App 的主線**完全照著給家長的提案**（`tutoring/小三英文規劃/05_家長提案_新版.pdf`）走，
首頁就是那三段，不多不少：

| 首頁 | 內容 | 提案裡的時段 |
|---|---|---|
| ① 複習昨天的 5 個字 | 圖＋中文 → 自己想 → 翻答案 → 自評 | 0–3 分 |
| ② 今天的 5 個新字 | 聽 → 說 → 看 → 拆 → 寫（最後接抄寫單） | 3–18 分 |
| ③ 蓋起來默寫 | 圖＋中文 → 寫在練習本上 → 翻答案對一對 | 18–20 分 |

① 和 ③ 是同一支程式 `startRecall(uid, mode)`，差別只在拿哪個單元和文案（`RC` 常數）。
**兩段都是自評，不自動判分**——提案講的就是「寫在練習本上」，字在紙上，App 只負責出題、
翻答案、記下哪幾個字要明天先練。

`③ 蓋起來默寫` 的結算會列出寫錯的字並說「圈起來，明天先練」，
隔天這些字**排在 ① 的最前面**並帶「⚠️ 上次沒記得」標記（`startRecall` 先洗牌再依
`store.wrong` 穩定排序，同分維持隨機）。標記只說「上次沒記得」，不透露答案。

## 今日任務＝那三段，不多不少

`DAILY_DEFS` 的設計原則是：**做完今天的 20 分鐘 ⇔ 任務剛好全滿**。
四格對應 ①、②（拆成「學」與「寫」，提案的 ② 本來就含兩件事）、③。

> v6 踩過的雷：改完流程忘了改 `DAILY_DEFS`，還留著「學 8 個單字」（一天只有 5 個）
> 和「完成 1 次闖關」（拼字磚已降級成加碼練習）。結果**照著做反而拿不到獎勵**，
> 「🎁 今日任務全部完成」永遠不會出現。**動流程就要同步動獎勵層。**

成就同理：主線有 ⚡二十分鐘（三段全做完）、✏️默寫全對；
舊的「完美闖關」「連擊高手」留著沒砍，因為拼字磚仍解得開，砍掉會讓已解鎖紀錄消失。

### 為什麼砍掉選擇題

原本有「🔊 聽音選字」「🔤 看字選意思」兩個四選一關卡，v6 拿掉了。
四選一是**認得出來**，提案整套要的是**想得出來**——給了四個選項就等於給了提示，
跟提取練習牴觸。只留「🧱 拼字磚」當加碼練習（在單元頁裡）。

**為什麼拼字用字母磚不用打字**：八歲的孩子英打很慢，用鍵盤的話一題有一半時間在找按鍵，
練的會變成打字而不是拼字。Anki 的 `{{type:}}` 卡有同樣問題（見工具比較文件）。

## 練習本與 App 怎麼接起來

家長很重視「寫」，所以有紙本練習本；但純抄寫效果差，所以做成閉環：
① 想不出來的字 → 進單字寶箱 → ② 今天照樣要寫 → ③ 默寫寫錯的 → 隔天 ① 先練到。
答對三次才移出寶箱。

**每個字寫 5 次，但 5 次動作不同**：前 2 次看著抄（同時唸出來），**後 3 次蓋起來寫**。
家長看到的還是「寫五次」，實質上後三次是提取練習——這是刻意設計，不是妥協。

清單**每天固定**（同一天重開 App 不會換一份新的字），存在 `store.write`。

## 單元 ＝ 日期

一個單元就是一天，固定 **5 個字**，全部都要寫（不是只挑錯的）。
首頁的「今天的功課」自動對應到今天日期的單元；今天沒有單元就跳到第一個還沒寫完的。

沒有拼讀／詞彙的分別了，全部都是詞彙單元。

## 圖片：ARASAAC，不是 Google

`img/<單字>.png`，由 `fetch_images.py` 從 **ARASAAC**（西班牙 Aragón 政府的溝通輔具圖庫）抓下來。

```bash
python3 fetch_images.py            # 只補還沒有的圖
python3 fetch_images.py --force    # 全部重抓
```

- **不能用 Google 圖片**：搜出來的圖絕大多數有版權，抓下來放進這個公開 repo 就是侵權。
- ARASAAC 授權 **CC BY-NC-SA**，非商業教學用途可用，出處標在 App 的「❓ 怎麼玩」頁面底部。
- 抓 `https://static.arasaac.org/pictograms/{id}/{id}_300.png`：彩色、300×300、約 8KB。
  ⚠️ 不要改用 API 的 `?resolution=500`（18–29KB），也不要拿 `sips` 縮圖（重新編碼後反而漲到 38KB）。
- `bestsearch` 的第一名有時語意對不上（fish 挑到「盤子裡的魚料理」、bag 挑到紙購物袋、
  rice 挑到稻穗），所以腳本裡有 `OVERRIDE` 表指定正確 id。**加新字後要逐張看過**。
- 抽象詞是最大風險。`big` ARASAAC 只有紅方框比大小或 XL 吊牌，小三看不懂，
  所以 `img/big.png` 是**手工合成的**（同一隻大象一大一小並排）。腳本會跳過已存在的檔，不會蓋掉。
- `words.js` 的 `emoji` 欄位是**退路**：圖檔 404 時 `onerror` 會換成 emoji，
  離線第一次開、或新字還沒抓圖，都不會開天窗。**不要拿掉這個欄位。**
- 動詞可以加 `anim` 欄位（`hop`／`shake`／`pulse`）做 CSS 微動效，
  只在「看」和翻答案時播，**抄寫單不播**（寫字時會分心）。沒有用 GIF。

## 分工：紙本學新字，App 複習舊字

2026-09-12 定案的使用方式，跟原本「孩子每天在家自己跑三段式」不同：

| 時機 | 工具 | 做什麼 |
|---|---|---|
| 平日在家 | **紙本練習本** | 學當天的新字，走五步驟（聽→說→看→拆→寫）。版面見 `tutoring/小三英文規劃/06_練習本怎麼寫_範例.png` |
| 平日在家 | App | ① 複習**單字庫**的舊字　② 開抄寫單當紙本的**對照表**　③ 蓋起來默寫 |
| **週末上課（六日）** | **App「👨‍🏫 上課模式」** | 只練**該週的新字**，全部考一次，不碰單字庫 |

**日子決定練什麼**（太一 2026-09-12 定的規則）：
- **週一～五**：App 複習**單字庫**（累積的舊字）；新字在紙本上學
- **週六日上課**：App **只練該週的新字**，不限題數、全部考過一次

「這一週」是從**本週一算到今天**（`weekStart()`），所以週六和週日都會抓到同一週的
週一～週五。不要用「最近 N 天」這種滾動區間——跨週會糊掉。

**為什麼這樣分**：學新字需要大人在旁邊示範發音、盯字型，那是紙本＋老師的場子；
舊字的保留靠「量」和「間隔」，那是程式的場子。而且家長一週只給約 5 個字，
餵不飽一個每天要開的 App —— 改成複習累積的舊字之後，題庫才自給自足。

## 👨‍🏫 上課模式（老師帶，會留成績）

首頁最下面進去。跟每日三段式**完全分開**——上課模式跨單元出題、不碰 `store.flow`。

1. **選範圍**：⭐這一週的新字／上一週的新字／單字庫｜還沒精通／單字庫｜錯過的字
2. **選題數**：預設**全部**（週末上課不限題數），也可以 10 / 15 / 25
3. **選題型**：看中文想英文（老師判對錯）／拼字磚（自動判分）

出題順序是 **Leitner 盒號小的先出**，不熟的字先被考到。未來日期的單元不會出題。

跑完存一筆成績（日期、範圍、題型、對幾題、沒過哪些字），在「📋 上課紀錄」看得到。
⚠️ 成績存在 `ewq_exams_v1`，**跟進度分開** —— 小孩按「清除全部紀錄」不會把老師的成績刪掉。

### 回想卡的 list 每一項是 `{uid, w}`

上課模式會跨好幾個單元出題，**計分的 key 必須跟著各自的單元走**，不能用整場共用的一個
`R.uid`。所以 `S.rc.list` 統一成 `{uid, w}` 配對，`grade()` 用 `it.uid` 而不是 `R.uid`。
改回想卡的程式碼時要注意這點。

## ⚠️ 進度的 key 只認單字，不認日期

`keyOf(uid, w)` **只回傳小寫的單字本身**，`uid` 參數留著只是為了不動十幾處呼叫端。

> v9 以前是 `"日期|單字"`。結果只要把某個字換到別的日期（改課表、重排單元、重灌
> `words.js`），那個字的 Leitner 盒號和錯誤次數就整個對不上，**等於被清掉，而且不會有
> 任何錯誤訊息**。2026-09-12 把單元從 9/14 改成 9/12 時就真的發生過一次。
>
> 字是同一個字，學會了就是學會了，跟它被排在哪一天無關。
> `migrateKeys()` 會把舊 key 併過來（盒號取 max、錯誤次數相加），只跑一次（`store.keyv`）。

⚠️ **不要因為改資料結構就去 bump `LS_KEY`** —— 那會讓所有人的進度歸零。要改結構就寫 migration。

## 💾 備份／還原

老師模式底部進去。改版**不會**清掉 localStorage，但這些會：
換裝置、清瀏覽器資料、無痕視窗、小孩誤按「清除全部紀錄」。

一次備份三個 key（進度／老師加的字／上課紀錄）成一段 JSON 文字，複製走；
還原時貼回來覆蓋。實測 `localStorage.clear()` 之後貼回去，XP、Leitner 盒號、
老師加的字、考試紀錄全部回來。

## 📦 已完成分區

單元一週加五天，一個月就會堆成一面牆。**過去日期的單元自動收進「📦 已完成」**
（`<details>` 摺疊，點開可以回去複習），首頁只留今天和接下來的。
判斷就是 `u.id < todayKey()`，不需要額外狀態。

## 👩‍🏫 老師模式：上課現場加單字

入口在「📊 我的進度」最下面（那頁本來就是給老師／家長看的）。**不設密碼**——小孩點進去
最多加幾個亂字，可逆，不值得為它加摩擦。

為什麼需要：家長給的字**不夠一週**。提案是週一到週五每天 5 字＝25 個，但實際只拿到
安親班某一班的 5 個拼字考單字。太一上課看到課本要能**當場**補字，而且當場就要能教，
不能等回家跑腳本。

貼上一段就好，一行一個字：

```
plant 植物
paper 紙 n. pa-per
recycle 回收 v.
```

解析規則刻意做成**順序無關**（現場打字才不會因為欄位順序錯就整行壞掉）：
第一個 token＝英文｜含 `-` 的＝音塊｜長得像詞性的＝詞性｜其餘串起來＝中文。
分隔接受空白／逗號／tab。

- **每 5 個字排一天，自動跳過週末**（提案是週一到週五）
- **圖即時從 ARASAAC 抓**——API 與圖片 CDN 都回 `access-control-allow-origin: *`，
  所以 iPad 上不用回電腦跑腳本。列表會顯示縮圖，**當場就看得出語意對不對**
- 音塊**預填自動切的結果、可以就地改**。自動切只處理單音節（沿用 `build_words.py`
  的原則），多音節留給老師填——他是老師，`pa-per` 十秒就打完，比讓程式猜錯好
- 「匯出給老師」產出的文字可以**直接貼進 `data/words.js`**，灌進去才會跟著上線給孩子

⚠️ **存在 `ewq_words_v1`，跟進度的 `ewq_state_v1` 分開**。「清除全部紀錄」是
`removeItem(LS_KEY)`，老師辛苦加的字不能跟著被小孩一起清掉。

## 音塊有三種狀態，不是兩種

```
sight:true   真的不規則（write / friend / said / Earth）→ ⭐「要整個記」
chunks 有值  照著拆
兩者皆無     只是還沒填音塊 → 什麼都不顯示
```

> v7 以前把「沒填」當成「不規則」（`w.sight || !w.chunks`，五處），於是
> **`paper`、`plastic`、`recycle` 這些明明拼得出來的字被教成整個背**。
> 自動切字只處理單音節，多音節一律留空，所以「留空」在這個系統裡是**常態**，
> 不是「這個字不規則」的訊號。要標成整個記，必須明寫 `sight:true`。

## 抄寫單：一口氣寫完當天的字

「📝 要寫的字」是這個 App 的主畫面：一頁列出當天 5 個字，每個字有
**圖 ／ 英文 ／ 詞性 ／ 中文 ／ 音塊**，照著抄進紙本練習本，寫完按「寫好了」。
頂端固定顯示五次的規則（前 2 次看著抄、後 3 次蓋起來寫）。

## 音塊怎麼拆（`chunks` 欄位的規則）

兩層，不要混用：

1. **多音節字先切音節**（一個母音「音」＝一個音節）：`pen-cil`、`hap-py`、`o-pen`
2. **單音節字切「首音 ＋ 韻腳」**：`c-at`、`sh-op`、`st-op`
3. **不再往下切成單一字母**——`-at` 當一整塊記，字族類推才生效；切成 `a-t` 就失效了
4. **母音開頭的單音節字**切「母音組合 ＋ 尾音」：`ea-t`
5. **不規則字不切**，標 `sight:true`（write、friend）

> v3 之前的資料混用了三種切法（`b-oo-k` 逐字素、`c-at` 首音韻腳、`hap-py` 音節），已統一。
> `build_words.py` 的自動切字只處理單音節（onset-rime），多音節一律留空要人工填——寧可空著不要切錯。

## Leitner 三盒

- 答對 → 往上一盒（0→1→2→3），**答對三次才變 💎精通**
- 答錯 → 一律退回第 1 盒，並進「寶藏袋」
- 出題比例：第 1 盒每次都出、第 2 盒出一半、第 3 盒出四分之一

## 換成安親班的真實單字

```bash
python3 build_words.py 安親班單字表.tsv     # 覆寫 data/words.js
```

TSV 格式看 `build_words.py` 的說明。單音節字的音塊會自動切（cat→c-at），
多音節字會留空並提醒——**寧可空著，不要自動切錯教壞小孩**。

## 本機跑起來

```bash
python3 -m http.server 8123
open http://localhost:8123/
```

⚠️ **改完程式看不到變化**：Service Worker 是 cache-first，會一直餵舊版。
開發時先在 Console 跑：

```js
for (const r of await navigator.serviceWorker.getRegistrations()) await r.unregister();
for (const k of await caches.keys()) await caches.delete(k);
location.reload();
```

發版時 `APP_VER`（index.html）和 `CACHE`（sw.js）**兩個都要改**，使用者端才會自動更新。

## 已知限制

- **音塊發音是逼近值**。TTS 唸單獨的子音會唸字母名稱（c → "see"），程式補了一個 uh
  變成 "cuh" 才唸得出「音」。這只是權宜；正確的音還是要老師當面示範。
- 地面的動物是固定 5 隻。蛋、圖鑑、商店、合成台都還沒做（第二階段）。
- **CSS class 命名要避開既有的**：`.wstep.cover` 撞到抽考的 `.cover`（`position:absolute; inset:0`），
  整頁被撐滿。已改成 `.s-cov`。加新元件前先 grep 一次 class 名。
- 沒有雲端同步，進度存在該裝置的 localStorage。換裝置＝重來。
- **單元 id 是日期字串**（`"2026-09-04"`），不是數字。`+c.dataset.uid` 會變成 `NaN`，
  整個「選一個單元」會死掉（v5 踩過這個雷）。碰到 uid 時不要轉型。
- 圖片**不能放進 sw.js 的 `ASSETS`**：`addAll` 只要有一張 404 就整包安裝失敗。
  改成 fetch handler 對 `/img/` 走 cache-first 再回填。
- **跨網域圖片的 SW 快取要認 opaque response**：`<img>` 抓 ARASAAC 是 no-cors 請求，
  回來的 response `status` 恆為 0、`ok` 恆為 false。只寫 `if (res.ok)` 的話一張都存不進去，
  離線就沒圖。要寫 `res.ok || res.type === "opaque"`。
- **不要把「一天 5 個字」寫死在畫面上**：老師加字後一天不一定剛好 5 個，
  會出現「要寫的 5 個字 ‧ 已完成 0/3」這種自打嘴巴的畫面。
- **`store.flow` 要存 `uid`**，不能只存 `ok/n`。同一天內把當天單元寫完後
  `todayUnit()` 會往前滾到下一個單元，首頁卡片就會拿新的單元標題去配舊的成績，
  顯示成別的日期。判斷「寫完了沒」也要用當下操作的 `R.uid`，不要用 `todayUnit()`。
